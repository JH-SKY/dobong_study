# 📚 오늘 배운 내용 정리 (이벤트 핸들링 & 스테이트 심화)

### 1. 학습 요약
사용자의 입력(Event)이 리액트의 보관함(State)에 어떻게 저장되고, 이게 다시 화면을 어떻게 바꾸는지 그 핵심 메커니즘을 파헤침.

---

### 2. 배운 개념 정리
* **이벤트 핸들링 (Event Handling)**: 사용자가 하는 모든 짓(클릭, 입력)을 감시하다가 함수를 실행시키는 장치. `onChange`가 대표적임.
* **스테이트 (State)**: 리액트가 화면을 새로 그리게 만드는 '방아쇠'. 값이 바뀌면 컴포넌트 전체를 처음부터 다시 실행함.
* **제어 컴포넌트**: `value`와 `onChange`를 묶어서 입력창의 주도권을 리액트가 꽉 쥐고 있는 상태.

---

### 3. 코드리뷰 (이벤트 & 스테이트 핵심)

```javascript
/* 1. 준비물 챙기기 (State)
비밀번호라는 데이터를 담을 '그릇'을 준비함. 
const [password, setPassword] = useState(""); 
*/

/* 2. 버튼 찾기 및 일 시키기 (Event Handling)
사용자가 키보드를 칠 때마다(onChange) 이 함수가 실행됨. 
*/
<input 
  value={password} // 3. 비유: value는 '현재 그릇에 담긴 내용물'임
  onChange={(e) => {
    // 1. e.target.value는 사용자가 방금 입력한 '따끈따끈한 새 데이터'
    // 2. setPassword는 그릇의 내용물을 새 데이터로 싹 갈아엎는 '교체 작업'
    setPassword(e.target.value); 
  }} 
/>

/* [설계 의도]
단순히 글자를 입력받는 게 아니라, 입력할 때마다 리액트가 그 값을 
가로채서 보관함에 넣어야 나중에 '일치 여부' 같은 계산을 실시간으로 할 수 있음.
*/
```

---

### 4. 헷갈렸던 점 (Q&A)
* **Q: `e.target.value`가 도대체 뭔가요?**
  * **A:** 이벤트가 발생한 **'목표물(target)'**인 input창 안의 **'값(value)'**을 의미함. 택배 상자(input) 안에 든 물건(value)을 꺼내는 과정이라고 보면 됨.
* **Q: 왜 그냥 변수 안 쓰고 굳이 `useState`를 쓰나요?**
  * **A:** 일반 변수는 값이 바뀌어도 리액트가 모른 척함. `set`함수를 써야만 리액트가 "어? 바뀌었네? 화면 다시 그려야지!" 하고 움직임.

---

### 5. 실무 관점
* **이벤트 최적화**: 실무에서는 `onChange`가 너무 자주 발생하면 성능이 떨어질 수 있어서, 아주 짧은 시간 동안 발생하는 이벤트들을 하나로 묶어 처리하는 기술(디바운싱 등)을 나중에 배우게 됨.
* **상태 관리의 정석**: 상태는 최소한으로 만드는 게 최고임. 오늘 배운 `isMatch`처럼 계산으로 나올 수 있는 건 굳이 `useState`로 만들지 않는 것이 실무자의 실력임.
