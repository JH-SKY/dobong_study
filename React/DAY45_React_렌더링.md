# DAY29_React_렌더링_및_데이터_처리_실습

#### 1. 학습 요약
React에서 데이터를 실제 화면에 그려내는 렌더링의 개념을 이해하고, map과 조건부 연산자를 활용해 데이터를 효율적으로 나열하고 제어하는 방법을 배웠습니다.

#### 2. 배운 개념 정리
* **렌더링(Rendering):** 작성한 코드가 브라우저 화면에 실제 그림으로 그려지는 전체 과정이에요. 마치 붕어빵 틀(코드)에 반죽을 부어 맛있는 붕어빵(화면)을 만들어내는 것과 같습니다.
* **리스트 렌더링 (map):** 여러 개의 데이터가 담긴 주머니에서 하나씩 아이템을 꺼내 동일한 HTML 태그에 담아주는 '친절한 배급원' 역할을 해요. 반복되는 UI를 만들 때 필수입니다.
* **조건부 렌더링 (&&, ? :):** 특정 상황일 때만 화면을 보여주거나 숨기는 '스위치' 기술이에요. "로그인했으면 사용자 이름을 보여주고, 아니면 로그인 버튼을 보여줘!" 같은 로직을 짤 때 사용합니다.
* **데이터 정렬:** 기준(가격순, 이름순 등)에 따라 데이터의 순서를 바꾸어 사용자에게 더 보기 편한 정보를 제공하는 기술입니다.

#### 3. 코드리뷰
오늘 배운 핵심 렌더링 기술들을 활용한 예시 코드입니다.

```javascript
import React from 'react';

function ProductList() {
  // 1. 준비물: 화면에 뿌려줄 데이터 주머니 (배열)
  const products = [
    { id: 1, name: '사과', price: 1000, inStock: true },
    { id: 2, name: '포도', price: 3000, inStock: false },
    { id: 3, name: '배', price: 2000, inStock: true },
  ];

  // 4. 데이터 정렬: 가격이 낮은 순서대로 정렬하기 (설계 의도: 사용자에게 저렴한 상품부터 노출)
  const sortedProducts = [...products].sort((a, b) => a.price - b.price);

  return (
    <div>
      <h1>과일 가게 상품 목록</h1>
      <ul>
        {/* 2. 리스트 렌더링: map이라는 배급원이 데이터를 하나씩 꺼내서 <li> 태그로 변환함 */}
        {sortedProducts.map((item) => (
          <li key={item.id}>
            {item.name} - {item.price}원 
            
            {/* 3. 조건부 렌더링: 재고가 없을 때만 '품절' 메시지를 보여주는 스위치 */}
            {!item.inStock && <span style={{ color: 'red' }}> (품절)</span>}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default ProductList;
```

#### 4. 헷갈렸던점
* **Q: map을 쓸 때 왜 자꾸 'key'를 넣으라고 에러(경고)가 뜨나요?**
* **A:** React라는 관리자가 화면을 다시 그릴 때, 어떤 항목이 바뀌었는지 정확히 알아야 하기 때문이에요. 이름표(key)가 없으면 모든 항목을 다 새로 그려야 해서 효율이 떨어지기 때문에, 고유한 ID를 이름표로 달아줘야 합니다.

#### 5. 실무 관점
실무에서는 수백, 수천 개의 데이터를 서버에서 받아옵니다. 이때 **리스트 렌더링**과 **정렬** 기능을 제대로 구현하지 못하면 사용자는 원하는 정보를 찾기 매우 힘들어해요. 특히 **조건부 렌더링**은 권한이 없는 사용자에게 특정 버튼을 숨기는 등 '보안'과 '사용자 경험(UX)' 측면에서 매우 중요하게 다뤄집니다.
