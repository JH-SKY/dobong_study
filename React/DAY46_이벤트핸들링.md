# DAY25_JavaScript_이벤트핸들링_정리.md

### 1. 학습 요약
사용자의 클릭이나 입력 같은 동작을 감지해 웹페이지가 반응하게 만드는 이벤트 핸들링의 본질과 JS/JSX의 차이점을 정리함.

### 2. 배운 개념 정리
* **이벤트 핸들링 (Event Handling)**: HTML로 뼈대 잡고 CSS로 꾸민 정적 페이지에 '신경망'을 까는 작업. 사용자가 하는 모든 행동(사건)을 조종(핸들링)하는 것임.
* **작동 원리**: Target(누가), Type(언제), Handler(무엇을) 세 가지만 정하면 됨. `addEventListener`가 이 셋을 연결하는 핵심 도구.
* **JS vs JSX**: 근본 엔진은 자바스크립트로 동일함. 다만 JSX는 '상태(State)'가 바뀌면 UI가 알아서 변하는 선언형 방식을 써서 관리가 더 편함.
* **자동완성 로직**: 사용자가 글자를 입력하는 `input` 이벤트를 실시간으로 감시해서 서버에 데이터를 요청하고 리스트를 뿌려주는 고난도 핸들링임.

### 3. 코드리뷰
```javascript
// [실습 코드: 조건부 이벤트 제어]

// 1. 타겟 요소 선택 (로그인/이동 버튼)
const moveBtn = document.querySelector('#move-button');

// 2. 핸들러 함수 정의: 단순히 이동만 하는 게 아니라 조건을 체크함
function handleMove(event) {
  const isLoggedIn = false; // 로그인 상태값 가정

  if (!isLoggedIn) {
    // 3. 원래 하려던 동작(링크 이동)을 강제로 막음
    event.preventDefault(); 
    alert("이종혁"); // 테스트용 알림창
  } else {
    // 4. 조건 만족 시에만 자바스크립트로 주소 변경
    window.location.href = "[https://www.google.com](https://www.google.com)";
  }
}

// 5. 클릭 이벤트와 핸들러 연결
moveBtn.addEventListener('click', handleMove);
```
**설계 의도**: 사용자의 모든 행동을 무조건 수용하는 게 아니라, 자바스크립트로 상황을 판단(조건문)하고 브라우저의 기본 동작을 제어(`preventDefault`)하는 실무 흐름을 파악하기 위함.

### 4. 헷갈렸던점
* **Q: alert는 언제 쓰는가?**: 실무용이라기보다 로직이 꼬였을 때 값이 제대로 들어오는지 확인하는 '공부용/테스트용'으로 매우 유용함.
* **Q: 모든 상호작용이 다 이벤트인가?**: 마우스 이동, 클릭, 키보드 타이핑, 스크롤, 심지어 파일 드래그까지 전부 이벤트 핸들링의 범주임.

### 5. 실무 관점
* **UX의 핵심**: 이벤트 핸들러를 얼마나 촘촘하게 짜느냐에 따라 "이 서비스가 내 행동에 빠릿하게 반응한다"는 느낌을 줌.
* **서버 부하 관리**: 검색 자동완성처럼 이벤트가 폭발적으로 일어날 때는 '디바운싱' 같은 기술로 서버에 요청 보내는 횟수를 조절해야 함.
