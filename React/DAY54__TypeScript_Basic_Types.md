# [DAY_54] TypeScript 기초: 정적 타이핑과 안정적인 JavaScript 개발

### 1. 학습 요약
* **TypeScript의 본질**: JavaScript에 '타입(Type)' 시스템을 더한 상위 집합(Superset) 언어
* **핵심 가치**: 런타임 에러(실행 중 오류)를 컴파일 단계(코드 작성 중)에서 방지하여 코드의 안정성과 유지보수성 극대화
* **주요 특징**: 정적 타이핑, 인터페이스 지원, 강력한 자동 완성 기능

### 2. 배운 개념 정리
* **정적 타이핑 (Static Typing)**: 변수를 선언할 때 데이터의 종류(숫자, 문자열 등)를 미리 결정하는 방식. 의도치 않은 타입의 데이터가 들어오는 것을 원천 봉쇄함
* **타입 추론 (Type Inference)**: 모든 곳에 타입을 명시하지 않아도, TS가 초기값을 보고 타입을 자동으로 판단하는 기능
* **인터페이스 (Interface)**: 객체(Object)의 구조를 정의하는 설계도. 특정 객체가 어떤 속성과 메서드를 가져야 하는지 규격화함
* **유니온 타입 (Union Type)**: 한 변수에 여러 타입 중 하나가 올 수 있음을 명시 (예: `string | number`)

### 3. 코드리뷰
실무에서 가장 자주 사용되는 **사용자 정보 관리** 예제로 타입스크립트의 기본 활용법을 검토합니다.

```typescript
// 1. 인터페이스 정의: 객체의 '설계도' 역할
interface User {
  readonly id: number;      // 수정 불가능한 읽기 전용 속성
  name: string;
  age: number;
  email?: string;           // 선택적 프로퍼티 (있어도 되고 없어도 됨)
}

// 2. 함수 타입 지정: 매개변수와 반환값의 타입을 명시
function getGreeting(user: User): string {
  // TS는 user.name이 문자열임을 보장하므로 안전하게 접근 가능
  return `안녕하세요, ${user.name}님! (ID: ${user.id})`;
}

// 3. 변수 선언 및 객체 생성
const newUser: User = {
  id: 1,
  name: "도봉개발자",
  age: 32
  // email은 선택 사항이므로 생략 가능
};

console.log(getGreeting(newUser));

// [에러 발생 예시]
// newUser.id = 2; // Error: 읽기 전용 속성이므로 수정 불가
// getGreeting({ name: "홍길동" }); // Error: id, age 등 필수 속성 누락
```

### 4. 헷갈렸던 점 (Q&A)
* **Q: JavaScript로도 충분한데 왜 굳이 타입을 써야 하나요?**
  * **A**: 혼자 작업할 때는 편할 수 있지만, 팀 단위 프로젝트나 규모가 커지면 `undefined`나 `null` 값으로 인한 에러를 잡기 매우 힘듭니다. TS는 이를 사전에 차단해 주는 '안전장치'입니다.
* **Q: any 타입은 만능 아닌가요?**
  * **A**: `any`를 남발하면 TypeScript를 쓰는 의미가 사라집니다. 가급적 구체적인 타입을 지정하고, 정 모를 때는 `unknown`을 사용하는 것이 권장됩니다.

### 5. 실무 관점
* **디버깅 시간 단축**: 실무 프로젝트에서 발생하는 에러의 상당수는 단순 타입 미스매치입니다. TS는 작성 시점에 빨간 줄로 알려주므로 배포 후 장애 발생 확률을 획기적으로 낮춥니다.
* **협업의 언어**: 인터페이스만 봐도 해당 함수가 무엇을 주고받는지 명확히 알 수 있어, 별도의 문서 없이도 코드가 그 자체로 훌륭한 설명서가 됩니다.
* **IDE 지원**: VS Code 등 편집기에서 강력한 자동 완성(Autocompletion)을 제공하여 오타 방지 및 개발 속도 향상에 기여합니다.
