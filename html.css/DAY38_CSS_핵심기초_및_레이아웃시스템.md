# 🎨 오늘 배운 내용: CSS 핵심 기초 및 레이아웃 시스템

### 1. 학습 요약
HTML 뼈대에 디자인을 입히는 별개의 스타일 시트 언어인 CSS의 기본 문법을 익히고, 요소 선택 방식과 우선순위, 그리고 웹 페이지의 구조를 결정하는 박스모델과 디스플레이 속성을 체계적으로 학습함.

### 2. 배운 개념 정리
* **CSS 기본 구조**: `선택자 { 속성: 값; }` 형식으로 이루어지며, HTML과는 별개의 언어로서 존재함.
* **선택자(Selector)와 우선순위**:
    1. **ID(#)**: 단 하나뿐인 요소. 힘이 가장 셈.
    2. **Class(.)**: 그룹화된 요소. 힘이 중간.
    3. **태그(tag)**: 해당 태그 전체. 힘이 가장 약함.
    * **Cascading**: 같은 힘끼리 맞붙으면 '위에서 아래로' 흐르는 규칙에 따라 가장 아래(나중)에 쓴 코드가 적용됨.
* **단위(Units)**: 
    - `px`: 절대적인 고정 크기.
    - `%`, `rem`, `em`: 주변 환경이나 부모 요소에 따라 변하는 상대적인 크기.
* **상속(Inheritance)**: 부모 태그에 적용한 스타일(예: 글자색)이 자식 태그에게도 물려 내려가는 성질.
* **박스모델(Box Model)**: 모든 요소는 사각형 박스 형태임.
    - `Content`: 실제 내용물.
    - `Padding`: 내용물과 테두리 사이의 안쪽 여백.
    - `Border`: 테두리 선.
    - `Margin`: 테두리 바깥쪽의 외부 여백.
* **디스플레이(Display)**:
    - `block`: 한 줄을 통째로 차지 (div, p, h1 등).
    - `inline`: 자기 내용물 크기만큼만 차지 (a, span 등).
    - `none`: 화면에서 아예 없애버림 (공간도 차지하지 않음).

### 3. 코드리뷰
```css
/* 실무에서 사용하는 구조적인 CSS 작성법 */

/* 1. 전체 초기화 및 상속 활용 */
body {
    font-family: 'Pretendard', sans-serif; /* 자식 요소들에게 폰트 상속 */
    color: #333333; /* 색상: 16진수 코드 사용 */
    margin: 0; /* 기본 여백 제거 */
}

/* 2. 박스모델 및 디스플레이 설정 */
.profile-card {
    display: block; /* 한 줄 차지 */
    width: 300px;
    margin: 20px auto; /* 상하 20px, 좌우 중앙 정렬 */
    padding: 15px; /* 안쪽 여백 */
    border: 1px solid #eeeeee; /* 테두리 */
    box-sizing: border-box; /* 패딩을 너비에 포함시키는 실무 필수 속성 */
}

/* 3. 선택자 우선순위 실습 */
.btn {
    background-color: gray; /* 클래스 선택자 */
    text-decoration: none; /* 밑줄 제거 (정답: none!) */
}

#submit-btn {
    background-color: #007bff; /* ID 선택자가 클래스보다 우선하여 파란색 적용 */
    color: white;
}

/* 4. 상태 선택자 */
.btn:hover {
    opacity: 0.8; /* 마우스 올렸을 때 투명도 조절 (UX 향상) */
}
```

### 4. 헷갈렸던점
* **Q: CSS는 프로그래밍 언어인가요?**
    - **A**: 엄밀히 말하면 '스타일 시트 언어'임. 계산이나 논리보다는 '디자인 명세'를 작성하는 용도임.
* **Q: null과 none의 차이는?**
    - **A**: 프로그래밍(JS)에서는 '값이 없음'을 `null`로 표현하지만, CSS 디자인 규칙에서는 효과를 없앨 때 `none`을 사용함 (예: `display: none;`, `text-decoration: none;`).
* **Q: ID 선택자를 많이 쓰면 좋은가요?**
    - **A**: 아니오. 힘이 너무 세서 나중에 덮어쓰기 힘들기 때문에, 실무에서는 재사용이 쉬운 `class` 위주로 설계함.

### 5. 실무 관점
* **UI/UX의 조화**: 단순히 예쁘게 만드는 것(UI)을 넘어, 버튼에 마우스를 올렸을 때 반응을 주거나(`:hover`), 적절한 여백(`margin/padding`)을 주어 사용자가 편안하게 느끼도록(UX) 설계하는 것이 개발자의 핵심 역량임.
* **유지보수**: 나중에 수정하기 편하도록 파일을 분리하고, 태그 선택자로 기본을 잡은 뒤 클래스로 세부 디자인을 입히는 계층 구조를 잘 짜야 함.
