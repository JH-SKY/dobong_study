# 📚 오늘 배운 내용 정리 (2026-02-24)

### 1. 학습 요약
HTML의 다양한 태그 분류와 상세 사용법을 익히고, 사용자의 데이터를 서버로 전달하는 핵심 관문인 Form 요소의 구조를 실습했습니다.

### 2. 배운 개념 정리
* **HTML 태그 분류**: 웹페이지라는 도화지에 제목(h1), 본문(p), 목록(ul/li) 등 용도에 맞는 '이름표'를 붙여주는 과정입니다.
* **HTML Form**: 사용자가 아이디를 치거나 버튼을 누르는 '입력창' 전체를 감싸는 큰 상자입니다. 이 상자가 있어야 우리가 입력한 정보가 AI나 서버로 안전하게 배달됩니다.
* **중첩 구조(Nesting)**: 큰 상자 안에 작은 상자를 넣는 방식입니다. 오늘 실습한 `table`처럼 `thead`와 `tbody`를 순서대로 잘 닫아주는 것이 문법의 핵심입니다.

### 3. 코드리뷰
```html
<table>
  <thead> <tr>
      <th>항목</th>
      <th>입력</th>
    </tr>
  </thead> <tbody> <tr>
      <td>이름</td>
      <td>
        <input type="text" name="user_name" placeholder="이름을 입력하세요">
      </td>
    </tr>
  </tbody>
</table>

<form action="/api/v1/chat" method="POST">
  <textarea name="question" rows="4">질문을 입력하세요.</textarea>
  <button type="submit">AI에게 물어보기</button>
</form>
```
* **주석 및 설계 의도**: 
  - `table` 내에서 `thead`와 `tbody`를 명확히 분리하여 데이터의 구조를 잡았습니다.
  - `input`과 `textarea`에 `name` 속성을 부여하여, 추후 파이썬(FastAPI 등) 백엔드에서 데이터를 식별할 수 있도록 설계했습니다.

### 4. 헷갈렸던점
* **Q: 태그를 닫는 순서가 왜 중요한가요?**
* **A**: HTML은 계층 구조입니다. 먼저 열린 상자(`<thead>`)가 나중에 열린 상자(`<tr>`)보다 먼저 닫히면 브라우저가 구조를 해석하지 못해 Prettier 같은 도구에서 에러를 냅니다. 항상 '안쪽 상자'부터 닫아야 합니다.

### 5. 실무 관점
* **왜 쓰는가?**: 우리가 만들 **AI 서비스 개발**에서 사용자의 질문을 받고 응답을 보여주는 모든 과정이 HTML로 이루어집니다. 
* **주의할 점**: 실무에서는 단순히 예쁘게 만드는 것보다 `name`이나 `id` 같은 속성 이름을 명확하게 짓는 게 중요합니다. 그래야 나중에 리액트(React)나 파이썬 코드가 이 태그를 정확히 찾아낼 수 있기 때문입니다.
