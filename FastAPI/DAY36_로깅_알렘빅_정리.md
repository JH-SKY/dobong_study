## 2. 📚 배운 개념 정리

### 🪵 로깅 (Logging) & 포맷터 (Formatter)
* **개념**: 프로그램의 모든 활동을 기록하는 '블랙박스'와 같음.
* **주요 속성**:
    * `%(asctime)s`: 로그 발생 시간
    * `%(levelname)s`: 로그 레벨 (INFO, WARNING, ERROR 등)
    * `%(filename)s:%(lineno)d`: **(핵심)** 에러가 발생한 파일명과 줄 번호
* **이유**: 일기를 쓸 때 '언제, 어디서'를 적어야 나중에 기억이 나듯, 코드에도 위치 정보를 남겨야 에러를 바로 검거(?)할 수 있음.

### ⚗️ 알렘빅 (Alembic)
* **개념**: 데이터베이스 설계도(Schema)의 버전 관리 도구.
* **이유**: 서비스 운영 중 DB 구조를 바꿀 때 기존 데이터를 보존하면서 안전하게 업데이트(마이그레이션)하기 위해 사용함.

### 🚫 .gitignore
* **개념**: Git이 추적하지 말아야 할 파일 목록을 정의.
* **대상**: 가상환경(`.venv`), 환경변수(`.env`), 로그 파일(`*.log`), OS 임시 파일 등.
* **이유**: 보안이 중요한 정보나 용량이 큰 불필요한 파일을 공유하지 않기 위함.

## 4. ❓ 헷갈렸던 점

> **Q. 에러가 나면 터미널에 자동으로 뜨는데 왜 직접 코드를 짜서 로그를 남겨야 할까?**

* **사고 과정**: "터미널(Traceback)만 보면 되는 거 아닌가?" → "아, 서버는 내가 보고 있을 때만 돌아가는 게 아니지!"
* **해결**: 터미널 에러는 프로그램이 죽을 때 내뱉는 **'일회성 비명'**임. 반면, 로깅은 서버가 24시간 동안 무슨 일을 했는지 기록하는 **'항구적인 일지'**임. 특히 사용자가 "어제 새벽에 안 됐어요"라고 문의했을 때 로그 파일이 없으면 원인 파악이 불가능함.

## 5. 🚀 실무 관점 (Insight)

* **디버깅 효율**: `%(filename)s:%(lineno)d` 설정 하나가 디버깅 시간을 **수 시간에서 수 분으로** 단축함.
* **보안 철칙**: `.gitignore`에 로그 파일과 환경 변수를 누락하는 것은 실무에서 **치명적인 보안 결함**으로 간주됨. 항상 프로젝트 시작 시 최우선으로 세팅해야 함.
* **데이터 보존**: 알렘빅을 사용하지 않고 DB를 직접 수정하는 행위는 실무에서 매우 위험함. 모든 DB 변경은 '마이그레이션 파일'을 통해 기록으로 남겨야 함.
